# Firebase concept room client handoff

This branch replaces the **browser** Supabase adapter and `/admin/` with Firebase Web SDK. The isolated room is deployed at `https://sinai-concept-room-dd26.web.app/`; the original GitHub Pages/Supabase site is still a separate writable site until a deliberate cutover. The old Supabase SQL and Node CLI are historical artifacts; `tools/concept-admin.mjs` is **not** a Firebase importer and must not be used against this branch.

## Build

Set the five public `PUBLIC_FIREBASE_*` variables from the actual Firebase Web SDK configuration in the build environment or in an **ignored** `.env.production` file. `.env.example` is documentation only and is not loaded by Astro. Never put service-account credentials in these variables. Run `npm ci`, `npm run build` (includes the fail-closed public-config check, Astro check and tests), and host `dist/` at the configured Astro base path. A build with missing or redacted configuration now fails; local `astro dev` still reports the missing connection instead of displaying demo records. Anonymous Authentication must be enabled. Test the actual deployed browser, including auth, catalogue and an authenticated `getBlob` from the hosting origin. A successful build alone cannot prove those work.

## Data contract / rules the infrastructure owner must implement

- `concepts/{sourceUUID}` contains the source snake_case concept fields plus `reviews: [source review rows]` and `concept_assessments: source assessment row | null`. Historical IDs and timestamp strings are retained. Catalogue reads query `where(locale == requested)` plus `where(publication_status == 'published')` for non-editors; editors query locale alone and see drafts. If Firestore requests an index, create it for the locale + publication_status pair. Each catalogue request needs exactly one concepts query; media is fetched separately only when visible/opened.
- `reviews/{id}` is create-only, never update/delete. On a review, one Firestore transaction sets the archive row and updates the concept's embedded `reviews` array. An editor decision/reset also changes `publication_status` in that transaction. New row keys: `id, concept_id, reviewer_id, reviewer_role, decision, notes, affects_decision, clear_prior_notes, supersedes_review_id, created_at`. `reviewer_id` is the current Firebase Auth uid; imported historical rows keep their source UUIDs. `wait` is legacy display-only, not a new decision.
- `concept_assessments/{conceptId}` and the embedded object update in one transaction, with `concept_id, production_speed, budget_level, updated_at, updated_by` (plus retained source fields). Category updates to the concept in the same transaction. Both assessment and editorial metadata writes require `profiles/{uid}.identity_kind == 'content_editor'`.
- `profiles/{firebaseUid}` is the active self-owned profile. The client explicitly selects a role and writes `display_name, identity_kind, is_editor, approved, created_at, updated_at`; `content_editor` is **open to every link holder**, as requested (no email allowlist). `legacy_profiles/{sourceUUID}` is a read-only archive; do not use those UUIDs for new authorship.
- `concept-banners/{sourcePath}` and `concept-pdfs/{sourcePath}` are private Storage keys. Legacy source paths are **not uniformly prefixed by their concept UUID**; imported objects carry `resource.metadata.conceptId`, which the deployed Storage rules compare against the referenced Firestore concept. New uploads set the same metadata. Readers access only published referenced assets (editors may access drafts), and writes require a self-selected editor. The client never calls `getDownloadURL`. It calls authenticated `getBlob`, creates transient object URLs, and revokes them on reader close, language switch, admin preview change, and pagehide. New file versions get new UUID folders and the old objects remain. Banner restoration is an optimistic-concurrency pointer update.
- `/admin/` offers draft creation, existing concept text/locale/category/order/status/media editing, a manifest-backed bulk import, draft publishing, and versioned banner composition/title correction/restore. A newly created concept is written only after its uploaded objects are ready; an edit uses an optimistic transaction. Source history/assessment remain unchanged by metadata edits.

**Security note:** Since every link-holder can elect `content_editor`, this is an intentionally open editorial policy, not an invitation-based privilege boundary. Rules must validate payload ownership and consistency even under that policy. Do not expose private Storage objects through permanent token URLs. Firebase Web SDK reads require client-side environment values at *build time*. The live isolated site passed catalogue in English/Hebrew, editor draft access, a private PDF, banners, and a temporary decision/comment write-read-delete exercise; raw source and private verification receipts remain outside Git. This does **not** automatically change the existing GitHub Pages address.
